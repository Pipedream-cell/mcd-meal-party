# 麦麦开饭局

将一桌人的偏好变成可解释的分餐清单。使用者需自行在麦当劳开放平台激活个人 MCP Token，并连接 `https://mcp.mcd.cn`。本 Skill 为独立开发的非官方作品。

## 获取真实信息

收集人数、成员代号、总预算、偏好、回避条件、就餐方式和用户提供的门店或地点。不要索取无关身份信息。预算包含配送等额外费用；尚未知的费用必须明确标注。

先发现服务端工具和实时 inputSchema，按 schema 组织参数，不猜测字段。可直接调用已连接的麦当劳 MCP；也可在项目根目录执行 `npm run mcp:tools` 和 `node --env-file-if-exists=.env src/cli.js call <工具名> <参数.json> .local/<结果.json>`。仓库路径是安装本 Skill 时使用的项目根目录；不要假定当前工作目录就是该目录。

按需调用 `now-time-info`、`query-nearby-stores`、`query-meals`、`query-meal-detail`、`query-store-coupons`、`calculate-price`；用户关心营养时才调用 `list-nutrition-foods`，关心当日活动时调用 `campaign-calendar`。本项目的客户端拒绝下单、兑换、领券、抽奖和地址修改等写操作。

## 形成候选集

仅从用户选定门店、就餐方式及时间对应的可售选项中选择。用 `query-meal-detail` 核实套餐组成和必选项，把已经补齐全部必选项的完整餐品/套餐作为一个候选选项。不要将单个配菜误当完整一餐。

将实际返回的数据映射为规划输入；规范见 [输入格式与核价](references/input-format.md)。若无法确认价格单位、完整套餐组成或回避条件，先核实。不能把不存在的标签解释成“不含该成分”。真实用户、地点和账户返回值只写入被 Git 忽略的 `.local/`。

## 计算与核价

到店自取、套餐默认组成、无领券/会员购买需求时，可使用 `node --env-file-if-exists=.env src/cli.js live <请求.json>`，请求格式见仓库 `examples/live-request.json`。先查询并确认当前门店和候选编码。该流程自动获取详情、组装默认子项、按单份官方试算价规划并试算最终篮子，核对商品数量；读取 `officialQuote`、`officialQuoteAt` 与 `withinBudget`，不要把内部 `plan` 的估算作为最终报价。请求中的偏好可使用官方标签或默认子项的完整名称，CLI 不推断同义词。回避条件缺少明确依据时返回待核实；复杂替换和外送使用下面的手动流程。

执行 `node src/cli.js plan .local/team.json --json`。算法在预算内依次最大化最低个人偏好命中数、全员偏好总命中数，最后最小化费用。每个成员一份完整餐品/套餐；不处理共享拼盘拆分、组合优惠优化或限量库存分配。

若无可行选项，说明哪位成员需要补充信息；若预算不足，返回最低所需预算和差额。不要移除成员、忽略回避条件或用虚构优惠凑预算。

把候选篮子映射回官方餐品编号、规格、套餐必选项，再按服务端 schema 调用 `calculate-price`。折扣互斥、限购、时段、配送费均以官方结果为准。若试算超预算，使用核实后的价格重算，最多三轮；仍不满足就报告原因。不得把 demo 数据或菜单加总标成官方最终价，也不得声称组合一定最省钱。

输出每人分餐、命中偏好、餐品数量、门店与查询时间、餐费/配送费/优惠/应付及预算余额。核价失败则明确保留“未核价”状态。本 Skill 不代为下单或付款，用户可在官方渠道继续。

过敏需求需用户向官方或门店确认；标签筛选无法排除交叉接触风险。不生成医疗或营养专业结论。
